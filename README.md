# Петушиная арена · Telegram Mini App

Бесплатная игра с 10-секундными боями, прокачкой петуха и тремя слотами экипировки. Одна игровая валюта — монеты — нужна для покупок и ставок 10, 25, 50 или 100. Есть боты с двухсекундной рулеткой соперника, подбор живого игрока с той же ставкой и первый бесплатный бой. До 90 касаний усиливают шансы; выбора стоек и тренировки за энергию нет. Валюта не имеет денежной стоимости и не выводится.

Это рабочий MVP для одного сервера: Python/Flask, SQLite и интерфейс без сборщика на HTML/CSS/JavaScript. Правила, кошелёк и результаты боя вычисляет сервер. Telegram нужен для настоящих аккаунтов; локальный режим запускается без токена.

Переключатель RU / EN в шапке меняет язык интерфейса и сохраняет выбор в браузере. В бою можно кликать или нажимать пробел: каждый отдельный удар запускает анимацию. Компактная карточка «Последний бой» остаётся на арене до следующего результата и восстанавливается после перезагрузки.

## Правила v4

Порода умножает суммарную мощь базы, уровня и экипировки: ×1 / ×1,2 / ×1,5 / ×1,9; итог округляется вниз один раз. Новые бои принимают до 90 кликов за 10 секунд без ограничения скорости. Во время боя показан серверный шанс по принятым кликам: при равной мощи против бота он растёт с 50% до 58,33%.

Целевой валовой возврат ставок на ботов (RTP) — 90% без кликов и 105% при 90 кликах до округления приза. Это отдельный показатель от шанса победы. Минимум 90% был и в v3; прежнее значение 80 относилось к лимиту кликов. Формулы и примеры — в [игровом дизайне](docs/GAME_DESIGN.md#бой-с-ботом).

Всплывающее окно победы или поражения закрывается крестиком либо через 4 секунды после показа; кольцо вокруг крестика показывает оставшееся время. Переключение языка и обновление состояния не запускают отсчёт заново. Компактная карточка «Последний бой» и история сохраняются после закрытия окна.

При обновлении остановить старые web/worker-процессы, сохранить резервную копию базы и обновить страницу клиента. Миграция 004 пересчитывает только кэш рейтинга мощности и очищает неоплаченную очередь. Балансы и снимки боёв не меняются: уже начатые v3-бои сохраняют 80 кликов и прежний движок.

## Обновление старой установки до экономики v3

Перед первым запуском нового кода остановить **все прежние web/worker-процессы**, создать согласованную резервную копию SQLite и обновить клиентскую страницу. Миграция применяется автоматически при следующем запуске приложения или worker; редактирование исходников само по себе её не запускает. Одновременная работа старого и нового кода с этой базой не поддерживается.

Новый баланс в сотых долях монеты равен `(старые монеты + 10 × старые медали) × 100`. Старые колонки и журнал сохраняются как архив, новый журнал получает единственную запись начального баланса. Бои v1/v2 завершатся по прежним правилам с переводом наград в новую валюту. Неоплаченная очередь очищается. Подробности и ограничения отката — [в архитектуре](docs/ARCHITECTURE.md#миграция-на-одну-валюту).

## Быстрый запуск без Telegram

Нужен Python 3.9 или новее. В репозитории подготовлены `.env.example` и локальный `.env`; секреты из `.env` не следует публиковать.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
# Создать .env со случайным секретом, только если файл отсутствует:
.venv/bin/python - <<'PY'
from pathlib import Path
import secrets
path = Path('.env')
if not path.exists():
    template = Path('.env.example').read_text()
    path.write_text(template.replace('replace-with-a-random-secret-of-at-least-32-characters', secrets.token_hex(32)))
    path.chmod(0o600)
PY
.venv/bin/python -m roosters
```

Открыть [http://127.0.0.1:8000](http://127.0.0.1:8000). Локальный вход включён при `APP_ENV=development` и `ALLOW_DEV_AUTH=true`. Для проверки PvP открыть два разных профиля браузера: отдельные игровые аккаунты создадутся автоматически, затем оба игрока должны начать поиск. Перезагрузка страницы восстанавливает аккаунт и активный бой. Сервер создаёт SQLite и применяет миграции автоматически.

Тестовые аккаунты отделены от Telegram-аккаунтов: они не увеличивают счётчик реальных игроков и не попадают к ним в очередь.

## Проверки

```sh
.venv/bin/python -m pytest -q
```

Тесты используют временные базы и подменённый Telegram API. Они не отправляют сообщения и не затрагивают игровую базу. Правила боя отделены от HTTP и проверяются независимо. Сценарии сервиса проверяют операции с валютой, повтор запросов и восстановление состояния.

Результаты проверок и ограничения — [docs/VERIFICATION.md](docs/VERIFICATION.md). Для повторной проверки текущего кода используй команды выше и ниже.

Тесты клиентской логики требуют Node.js:

```sh
node --test web/tests/*.test.mjs
```

Браузерные проверки устанавливаются отдельно от обычных тестов:

```sh
.venv/bin/python -m pip install -r requirements-browser.txt
.venv/bin/python -m scripts.check_browser
```

На macOS сценарий автоматически использует установленный Google Chrome. Другой путь можно передать через `--chrome /path/to/chrome`; если системного браузера нет, сначала выполнить `.venv/bin/python -m playwright install chromium`. Скриншоты сохраняются в `artifacts/` или в папке из `--artifacts-dir`.

Браузерный сценарий использует отдельную временную базу и подменяет Telegram SDK. Он проверяет мобильный интерфейс и игровой путь в настоящем браузере; реальный запуск через Telegram всё равно требует токена и HTTPS.

## Подключение Telegram

Бота можно проверить с ноутбука уже после заполнения `BOT_TOKEN` и `BOT_USERNAME` без `@` в `.env`:

```sh
.venv/bin/python -m scripts.bot
```

Он получает команды через **long polling**, без webhook и входящего публичного адреса. Пока `WEBAPP_URL` пуст или содержит адрес-заглушку из шаблона, `/start`, `/play` и `/help` подтверждают работу бота без кнопки игры. Терминал должен оставаться открытым; остановка — `Ctrl+C`.

Для самой игры **внутри Telegram** нужен публичный HTTPS-адрес HTTP-сервера. HTTPS-туннель выдаёт такой адрес и пересылает запросы на запущенную на ноутбуке игру. Туннель и long polling решают разные задачи: первый открывает доступ к Mini App, второй доставляет команды боту. На своём сервере polling можно сохранить или позднее реализовать приём webhook. Подробная инструкция — [docs/TELEGRAM_SETUP.md](docs/TELEGRAM_SETUP.md).

1. Заполнить `BOT_TOKEN`, `BOT_USERNAME`, `WEBAPP_URL` и случайный `SECRET_KEY` в `.env`.
2. Для публичного сервера установить `APP_ENV=production` и `ALLOW_DEV_AUTH=false`.
3. Запустить HTTP-сервер за reverse proxy с HTTPS.
4. Один раз выполнить `.venv/bin/python -m scripts.set_menu` для кнопки меню.
5. Запустить `.venv/bin/python -m scripts.bot`, открыть личный чат бота и отправить `/start`.

Bot API вызывается только при отдельном запуске этих скриптов. Сам игровой сервер не запускает бота и не рассылает сообщения.

## Развёртывание

Для Python-окружения на Linux/macOS:

```sh
.venv/bin/gunicorn --workers 2 --threads 4 --bind 127.0.0.1:8000 'roosters:create_app()'
```

Все процессы должны использовать **одну SQLite-базу на локальном диске одного хоста**. Не размещать её на сетевой файловой системе и не запускать несколько реплик приложения с разными базами. Настроить HTTPS reverse proxy, перезапуск процесса и резервное копирование через SQLite backup API: он создаёт согласованный снимок с учётом данных WAL. Не копировать только `.sqlite3` во время записи.

Docker запускает непривилегированного пользователя и сохраняет базу в именованном томе:

```sh
docker compose up --build -d
# Включает отдельно запускаемый Telegram launcher:
docker compose --profile telegram up --build -d
# Однократная настройка меню после заполнения .env:
docker compose run --rm bot python -m scripts.set_menu
```

Порт Docker опубликован только на `127.0.0.1:8000`; внешний HTTPS предоставляет reverse proxy. Для bind mount вместо именованного тома владельцу папки данных требуется UID/GID `10001:10001`. Образ не содержит `.env`, токен, тестовые базы или окружение разработчика.

Бои завершаются при обращении к состоянию игрока. Чтобы завершать их и без открытого клиента, можно отдельно запустить `.venv/bin/python -m roosters.worker` с тем же `.env` и той же базой. В Docker Compose этот worker запускается по умолчанию вместе с web.
