# Проверки правил и интерфейса

Это журнал проверок разных этапов, а не результат нового запуска. Последний
полный прогон после обновления дизайна — [FINAL-POLISH](design/FINAL-POLISH.md#verification)
(173 Python-теста, 52 Node-теста и browser suites). Текущие команды и выбор
проверок для следующей задачи — [руководство по дизайну](design/README.md#как-проверять).

## Проверка v4 до визуальных волн — 25 сентября 2026 года

Повторная сверка документации с кодом: множители пород, 90 кликов, серверная
вероятность и уведомление результата на 4 секунды. Менялась только документация;
существующие проверки выполнены на временных базах, без запуска Telegram-бота
и изменения пользовательской базы.

| Проверка | Результат |
| --- | --- |
| `.venv/bin/python -m pytest -o addopts='' -q` | 173 теста прошли |
| `node --test web/tests/*.test.mjs` | 34 теста прошли |
| `node --check web/app.js` и `node --check web/i18n.mjs` | Синтаксических ошибок нет |
| `python scripts/check_browser.py --artifacts-dir /private/tmp/roosters-v4-docs-verification-20260925` | Полный сценарий Chrome прошёл; ошибок JavaScript нет |

Сверенные правила и серверные проверки:

- Порода умножает всю базу, уровень и экипировку с одним округлением вниз:
  ×1 / ×1,2 / ×1,5 / ×1,9. Мощь обновляется в состоянии и рейтинге.
- Бой длится 10 секунд, принимает до 90 кликов без ограничения скорости.
  Целевой RTP бота до округления приза — 90% без кликов и 105% при 90.
  При равной мощи вероятность победы растёт с 50% до 58,33%.
- `current_win_probability` рассчитывается по принятым кликам; итоговый шанс
  и результат не раскрываются заранее. Ставка, соперник и приз сохраняются.
- Миграция 004 сохраняет баланс, журнал и созданные бои, пересчитывает мощь
  и очищает неоплаченную очередь; повтор не выполняет её снова. Начатый v3-бой
  сохраняет прежние снимки, приз и предел 80 кликов.
- Продолжают проходить проверки кошелька, UUID, потерянных ответов, конкурирующих
  команд, PvP-выплат и исторических движков v1/v2/v3.

Chrome проверил 90 кликов одним запросом, рост текущего шанса, покупку медной
породы с изменением мощи `110 × 1.2 = 132`, окно победы и поражения, убывание
кольца, закрытие крестиком и автоматическое исчезновение через 4 секунды.
Обновление состояния не перезапускает отсчёт, показанный результат не появляется
повторно после reload. Пройдены прежние сценарии выплат, PvP, восстановления
запросов, постоянной карточки, RU / EN, пробела, анимаций и reduced motion.
Проверены размеры 320/390/1280 px; кнопка боя помещается над нижним меню на
390×844. Скриншоты боя и победного уведомления просмотрены вручную.

Node отдельно проверяет отображение множителя и серверного шанса с лимитом 90,
таймер и закрытие окна. Сценарий отправки пачки в Node пока использует фикстуру
с лимитом 80; проверка полной пачки из 90 выполнена в Chrome через настоящий API.

Артефакты текущего прогона: `/private/tmp/roosters-v4-docs-verification-20260925/`,
включая `battle-mobile.png`, `result-toast-mobile.png`, `victory-toast-mobile.png`
и `arena-english-mobile.png`. Использован установленный Playwright из соседнего
локального окружения и системный Chrome; их исходники и данные не менялись.
Временный HTTP-сервер остановлен после проверки.

Настоящий Telegram SDK, VPS, Docker, HTTPS-прокси, нагрузка и удалённый CI в этом
прогоне не проверялись. Ниже сохранён отчёт прежней версии; его числа и лимит 80
относятся к v3.

## Архив: v3 — 23 сентября 2026 года

Локальная проверка 23 сентября 2026 года. Все сценарии используют временные
базы; пользовательская база не изменялась. Telegram API в тестах заменён
заглушками, launcher не запускался.

| Проверка | Результат |
| --- | --- |
| `.venv/bin/python -m pytest -o addopts='' -q` | 168 тестов прошли на Python 3.9 |
| `node --test web/tests/*.test.mjs` | 32 теста прошли на Node 24: 20 клиентских и 12 для локализации |
| `node --check web/app.js` | Синтаксических ошибок нет |
| `python scripts/check_browser.py` | Пройдено в системном Chrome через Playwright |

Серверные проверки покрывают:

- Точные рациональные вероятности, все целочисленные варианты рулетки для
  диапазона мощностей и всех ставок, границы округления RTP 90–105%.
- 80 кликов одной пачкой и в один момент, запрет до старта/после окончания,
  общий лимит, владение боем и повтор UUID без повторного учёта.
- Бесплатный первый бой, фиксированную награду при обоих исходах,
  одновременные старты из двух вкладок и отсутствие повторной выдачи.
- Фиксацию соперника, случайного числа, ставки и приза; потерянный ответ,
  перезапуск и одновременное завершение двумя workers.
- Равные ставки PvP, выплату 95% банка, откат при ошибке второго списания или
  начисления, гонку отмены и подбора в обоих порядках блокировки.
- Два порядка рейтинга; победы над ботами и тестовыми игроками не увеличивают
  реальные PvP-победы. Мощь обновляется при покупках и получении опыта.
- Миграцию `(coins + medals × 10) × 100` без изменения архивных журналов,
  повтор миграции, нулевой кошелёк и откат схемы/данных при сбое переноса.
- Исторические v1/v2 бои и команды; сохранённый v3 бой не становится
  медальным при будущей смене текущей метки версии.
- Подпись Telegram, срок сессии, запрет dev-входа в production,
  недоверенные поля, presence, очередь, ежедневные/пассивные/реферальные выдачи.

Клиент проверяется через Node VM и настоящий HTTP API в Chrome. Для Chrome
используется установленный Playwright из соседнего локального окружения;
приложение и временная база принадлежат этому проекту. Чужие исходники и данные
не меняются. Для повторения в своей `.venv` установить
`requirements-browser.txt` по инструкции в README.

Клиентские регрессии включают сохранение UUID после потерянного ответа,
восстановление сессии без отката баланса после покупки, все 80 кликов одной
пачкой, ставки в сотых монеты, отсутствие старых режимов и валют,
отсчёт подготовки/боя и корректные тексты исторических наград.

Chrome через настоящий HTTP API проверил проигрыш первого бесплатного боя
с наградой 15 монет, все 80 кликов одной пачкой, восстановление зафиксированной
рулетки после reload, дневной/пассивный доход, покупки, потерянный ответ старта
и покупки, платное поражение с нулевой выплатой, подбор по одинаковой ставке,
PvP двух контекстов с выплатой 47,50 из банка 50 и оба рейтинга.
Все четыре вкладки проверены на ширинах 320/390/1280 px: переполнения и ошибок
JavaScript нет. Кнопки первого боя и поддержки в бою видны над нижним меню
на экране 390×844 без прокрутки. При reduced motion рулетка статична.

Скриншоты последнего прогона: `/private/tmp/roosters-language-browser-artifacts/`:
`onboarding-mobile.png`, `battle-mobile.png`, `arena-mobile.png`,
`arena-desktop.png`, `arena-english-mobile.png`. При обычном запуске скрипт сохраняет их в `artifacts/`;
путь можно изменить параметром `--artifacts-dir`.

Локальный браузерный вход не подтверждает работу внутри настоящего Telegram.
В этой итерации не проверялись native Telegram SDK, VPS, Docker build/run,
HTTPS reverse proxy или производительность под большой нагрузкой.
CI для Python 3.9/3.12 описан в репозитории; удалённый CI не запускался.

### Анимация удара по клику

После добавления локального выпада, реакции соперника, взмаха и искр повторно
прошли 14 клиентских тестов, проверка синтаксиса JS и полный сценарий Chrome.
Дополнительно Chrome проверил мгновенный эффект до сетевого ответа, повторные
клики без накопления анимаций, сохранение тех же фигурок и движений при
ответе команды и polling, неподвижную кнопку кликов и остановку в конце боя.
При reduced motion остаётся только мягкий opacity-акцент; движения нет.
До старта и после окончания новые эффекты и запросы кликов не создаются.
Артефакты: `/private/tmp/roosters-hit-browser-artifacts/battle-hit-mobile.png`
и `battle-hit-reduced-mobile.png`. Прогон использовал временную базу;
сервер проверки завершён, пользовательская база и бот не затронуты.

### Управление пробелом

Прошли 14 клиентских тестов, проверка синтаксиса JS и полный Chrome-прогон.
Chrome проверил настоящий keydown/keyup: одно нажатие пробела даёт один тап
и анимацию, удержание не повторяет удар, сфокусированная кнопка не создаёт
второй клик при отпускании. Пробел на арене не прокручивает страницу; поля
ввода, contenteditable и другие кнопки сохраняют обычное поведение. До старта
и после завершения боя новых тапов нет. Артефакты последнего прогона:
`/private/tmp/roosters-space-browser-artifacts/`. Использовалась временная база.

### Последний бой и RU / EN

Прошли 32 клиентских теста, а также полный сценарий Chrome на временной базе.
Карточка результата остаётся после reload, во время следующего боя и поиска;
после завершения нового боя обновляется. Проверены сумма итога и отсутствие
кнопки закрытия, включая старый сохранённый флаг скрытия результата.

Проверены перевод всех четырёх разделов на английский, доступные подписи,
сохранение RU / EN после reload и шапка на ширине 320 px. Имена игроков и
инициалы аватаров сохраняются. Смена языка в активном бою оставляет те же
фигурки, анимации, идентификатор боя и принятые клики, не отправляя новых тапов.
Node проверяет сохранение UUID и тела неподтверждённой команды, буфера кликов,
перевод уведомлений и ошибок, отказ localStorage и экранирование имён.

Артефакты: `/private/tmp/roosters-language-browser-artifacts/`. Сервер проверки
завершён; пользовательская база и бот не затронуты. Серверные правила в этой
итерации не менялись, поэтому 168 backend-тестов в таблице относятся к предыдущей
проверке v3. Удалённый CI не запускался; в его команду включены оба набора Node.
